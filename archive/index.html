Build your own

Every page above is one HTML file that reads a grammar.json in the browser. No server, no build step. You can copy one into your own repo, change how it draws, and still have your grammars open in recursive.eco.

  1. 1

    How a page reads a grammar

    The page takes the grammar’s path in its address, ?src=../tarot/<slug>/grammar.json, fetches that file and draws its nodes: each node has a name, an image_url and sections (named texts). The format is written down at recursive.eco/docs/grammar-format.html. The smallest page that does it is deck.html + loader.js in the tarot repo (about 80 lines, no libraries).

  2. 2

    Copy it into your own repo

    Make a GitHub repo with your grammars at tarot/<slug>/grammar.json. Copy the page (archive/cards.html) and the helpers it loads (viewers/reference-resolve.js, viewers/grammar-loader.js, viewers/dimension-engine.js, viewers/deck-picker.js), and if you like the look, theme.css and the header. Keep the page one folder below the root, as here, so its ../ paths still land. Add an empty .nojekyll file (without it GitHub Pages hides every file whose name starts with _), then turn Pages on: Settings → Pages → Deploy from a branch → main, / (root). Your page is at https://<you>.github.io/<repo>/archive/cards.html?src=../tarot/<slug>/grammar.json. Change the drawing code as much as you like: the grammar stays the same file.

  3. 3

    Link your repo to recursive.eco

    Add a recursive-eco.json at the root of your repo (this site’s recursive-eco.json is a working example: a name, a slug, and where the grammars are). In recursive.eco, open Create → Import → Link a GitHub repo, paste your repo’s address, install the recursive.eco GitHub app on that repo, then tap Import them. Each grammar gets an id; write the slug → id pairs in a file like this site’s tarot/_eco_ids.json, and your page can offer “Open in Play”: https://recursive.eco/play?id=<id>.
